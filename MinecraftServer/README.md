# MinecraftServer

The household's personal [Minecraft](https://www.minecraft.net/) server
(`itzg/minecraft-server`, the de facto standard Docker image for
self-hosted Minecraft). Named after "KT PupHaus," the household's UniFi
site name, which also shows up as this server's `SERVER_NAME` in an
alternate, currently-commented-out block of the compose file. This is a
game server, not a web app — it needs no reverse proxy, no TLS, no OIDC,
just a single TCP port.

## Prerequisites

- Port `25565` free on the host (the standard Minecraft server port,
  published directly).
- Nothing else — this is a fully standalone stack with no dependency on
  any other stack, network, or secret in this repo.

## Running it standalone

About as portable as it gets. Clone just this folder, run
`docker compose up -d`, and connect a Minecraft client to
`<host-ip>:25565`. `EULA: "TRUE"` accepts Mojang's EULA on your behalf by
starting the container — read it first if you haven't. `pull_policy: daily`
means Docker will check for a newer image once a day on its own; this is
the one place in this whole repo with anything resembling automatic
updates (see the note below — it's still not a "Watchtower," just a
compose-native pull-policy setting scoped to this one service).

## How it fits into this homelab

- **No Traefik labels, no Docker network entries.** Game servers generally
  don't speak HTTP, so there's nothing for Traefik to route — the port is
  published directly and reached by IP, the same way most people run a
  personal Minecraft server.
- **Git Sync**: wired up like every other non-exempt stack, though there's
  very little here for it to actually sync — this compose file rarely
  changes.
- **Secrets**: only `MANAGEMENT_SERVER_SECRET`, which is referenced by the
  *commented-out* management-server block (see below), not the active
  service — as of this writing it isn't consumed by anything actually
  running.

## Notes / gotchas

- The compose file has two blocks: a header comment containing a fuller,
  **disabled** configuration (with `OPS`, a management server on port
  `25566`, and `MANAGEMENT_SERVER_SECRET`) generated by setupmc.com, and
  the actual **active** `services:` block below it, which is much simpler
  — just EULA acceptance and a data volume. If you want the management
  server or operator list from the commented block, they need to be
  merged into the active block manually; they aren't automatically
  layered on top of it.
- `pull_policy: daily` is the closest thing to an auto-updater anywhere in
  this repo — it's scoped to this one service's image pull behavior via
  Docker Compose itself, not a separate Watchtower-style container (no
  such container exists anywhere in this repo as of this writing; see the
  top-level README's open questions).
